# TU-403 지원금 물품 구매 증빙

한 신청은 거래명세의 한 품목을 청구한다. 동일 품목을 같은 개당 가격으로 여러 개 구매했다면 수량으로 표현한다. 한 결제의 서로 다른 물품은 같은 결제 식별 정보를 사용해 각각 신청한다. 검토와 승인은 기존과 같이 신청별로 진행한다.

## API

기존 `apiFnd001` 신청과 `apiFnd003` 수정에 아래 필드를 추가한다. 대표자 상세 `apiFnd002`와 집행부 상세 `apiFnd012`는 이 필드를 반환한다. 과거 신청 및 물품 구매 증빙을 사용하지 않는 신청은 해당 필드 없이 조회할 수 있다.

| 필드 | 의미 |
| --- | --- |
| `expenditureAmount` | 이 신청에 해당하는 품목의 결제액(원). 배송비와 다른 품목의 금액은 제외한다. |
| `purchaseReceipt.reference` | 같은 결제에서 동일하게 적는 거래처와 영수증·주문·승인 번호. 최대 128자. |
| `purchaseReceipt.totalAmount` | 영수증 전체 실결제액(원). 배송비를 포함해 영수증 결제액과 일치시킨다. |
| `purchaseReceipt.itemNumber` | 거래명세에 나타난 순서대로 매긴 1부터 시작하는 품목 번호. |
| `purchaseReceipt.quantity` | 해당 품목의 구매 수량. |

신규 비소프트웨어 비품 및 동아리용품 구매에는 영수증 정보가 필요하다. 기존 물품 구매에서 품목 분류나 금액·수량·단가를 수정할 때도 영수증을 연결한다. 영수증을 사용한 신청에서는 개수와 개당 가격을 품목 지출액과 영수증 수량으로 계산한다.

같은 동아리·결제일·결제 식별 정보의 신청은 전체 결제액이 일치해야 한다. 다른 활성 신청이 없으면 전체 결제액을 정정할 수 있다. 삭제되지 않은 신청끼리 품목 번호가 중복되거나 품목 지출액 합계가 전체 결제액을 초과하면 저장할 수 없다. 비품 구매의 개당 5만 원 기준은 `expenditureAmount >= 50_000 × quantity`로 판단한다. 정수 원 단위로 표현할 수 없는 개당 금액도 품목 결제액과 수량으로 조회하고 검증할 수 있다.

거래명세는 신청의 기존 증빙 파일로 제출한다. 검토자는 같은 품목만 입력했는지와 품목 번호 및 금액이 거래명세와 맞는지 확인한다. 배송비와 여러 품목에 걸친 할인이 있는 경우에는 거래명세로 해당 품목에 귀속되는 실결제액을 확인한다. [동연 지원금 시행기준](https://cafe.naver.com/kaistclubs/34567) · [비품관리세칙](https://student.kaist.ac.kr/wiki/학부총학생회:동아리연합회칙:비품관리세칙)

## DB 적용

[`TU-403-funding-purchase-receipts.sql`](./TU-403-funding-purchase-receipts.sql)은 공통 결제 정보를 담는 `funding_receipt`와 `funding`의 선택 연결 컬럼을 추가한다. DB 변경을 API 배포에 앞서 적용한다. 과거 단가와 승인 금액을 재계산하는 작업은 없으며, 과거 행은 연결 컬럼이 비어 있는 상태로 남는다.
