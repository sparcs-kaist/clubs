# TU-500: 과거 HP·교환 학번 로그인 오류 및 교환학생 준회원 분류

## 문제와 정책

현재 SSO 학번의 학적 판정이 성공해도 연결된 과거 HP·교환 학번의 학위를
판정하지 못하면 로그인 전체가 롤백됐다. 토큰 갱신과 대리 로그인도 같은
학생 프로필 조회를 사용해 실패할 수 있었다.

- 현재 SSO 학번은 지원하는 학생 프로필로 판정돼야 한다. 현재 학번이 HP이면 계속 차단한다.
- 연결된 HP 학번(끝 네 자리 6900 이상, 7000 미만)은 학위 enum 유무와 무관하게 제외한다.
- `StudentEnum.Exchange = 8`과 `exchangeStudent` 프로필을 추가한다.
- SSO V2 → 현재 유효한 DB 학위 → 학번 규칙 순으로 판정한다. SSO 프로그램 코드 `"8"`은 기존대로 석박통합(석)이다.
- SSO·DB 학위가 없는 학번의 끝 네 자리가 6000 이상이면 HP를 제외하고 교환학생 프로필을 제공한다. 현재·과거 학번에 모두 적용한다.
- 지원하지 않는 DB 학위 enum은 현재 학적이면 실패하고 과거 학적이면 해당 프로필만 제외한다.
- 현재 학적 검증 실패와 DB 조회·쓰기 장애는 계속 실패 처리한다.
- 로그인·토큰 갱신·대리 로그인 모두 사용 가능한 프로필이 없으면 실패한다.
- 현재 SSO에서 판정한 프로필은 재판정하지 않으며 같은 학위의 과거 프로필보다 우선한다.
- 학부·대학원 교환학생의 재학·휴학 로그인과 회원등록을 허용한다.
- 교환학생은 준회원이다. 정회원 판정은 기존 회원등록 기준인 학사이면서 학번 끝 네 자리 6000 미만을 사용한다.
- 과거 정규 학번의 기존 프로필 동작과 과거 학생·학적 원본 데이터는 보존한다.

## 변경 범위

공통 프로필 구성은 학위를 확인할 수 없는 특수 학번에 교환학생 프로필을 제공한다.
`findLoginIdentity`를 사용하는 토큰 갱신과 대리 로그인에도 같은 기준이 적용된다.
실패 진단의 연결된 학생 목록에는 제외 대상도 남긴다.

6000 이상이라는 학번 규칙 자체는 공식 교환학생 구분값이 아니다. 유효한 SSO·DB
학위를 우선하며, 만료된 과거 대학원 학적만 남아 있으면 교환학생으로 표시될 수 있다.
이 경우에도 과거 DB 학적은 변경하지 않는다.

회원등록의 기존 정회원 기준을 공통 함수로 옮겨 대표자 후보·변경과 총람의
정회원 수에도 적용한다. 학위·학번은 User 도메인의 기존 공개 조회를 사용한다.
총회원 수에는 준회원도 포함하며, 휴학 여부로 회원 활동을 제한하지 않는다.

SSO의 V1·V2 정보는 각각의 인증 경로에서 마지막으로 저장한 프로필이다.
학부·대학원 전용 필드가 아니며, 오래된 V1 정보로 현재 학위를 대신 판정하지 않는다.
V1은 진단용으로만 보존해 누락·파싱 오류가 유효한 V2 로그인을 막지 않게 한다.
실패 진단에는 두 버전의 마지막 갱신일도 원본 타입 그대로 기록한다.
근거: [SSO 프로필 저장 코드](https://github.com/sparcs-kaist/sparcssso/blob/51d17743037a9b2e56bbbeadfa14365b8077c106/apps/core/models.py#L251-L261).

## DB / API

- DB 스키마·FK·데이터 마이그레이션 없음.
- 로그인·갱신·대리 로그인 응답의 `accessToken`에 선택적 `exchangeStudent: string`을 추가한다. JWT의 `type`은 `exchangeStudent`이며 `studentId`·`studentNumber`를 포함한다.
- 기존 학위별 토큰을 유지하며 교환학생도 학생 API·연락처·프로필 선택을 사용할 수 있다. 학부 전용 권한은 부여하지 않는다.
- 프론트는 교환학생 단독 토큰도 선택하고 프로필 이름을 `교환학생`으로 표시한다.
- 사용 가능한 프로필이 없는 경우 기존 대리 로그인의 404 응답을 로그인·토큰 갱신에도 적용한다.

## 검증

- HP 범위 양쪽 경계와 정회원의 학위·학번 조건을 단위 테스트 및 MC/DC로 확인한다.
- 과거 HP + 현재 재학/휴학, HP 학위 enum 존재 여부, 로그인/갱신을 검증한다.
- 현재 HP 또는 지원하지 않는 DB 학위가 과거 정규 학번으로 구제되지 않음을 확인한다.
- 지원하지 않는 DB 학위 enum은 현재 학적이면 실패하고 과거 학적이면 제외한다.
- 현재 SSO 학번과 같은 학위의 과거 학번이 어느 순서로 조회되든 현재 프로필이 유지되는지 확인한다.
- 유효한 V2와 누락·형식 오류 V1의 조합, 진단 갱신일 보존, 모든 프로필 제외 시 토큰 미발급을 확인한다.
- 과거 교환 학번의 만료 학적 + 현재 SSO 코드 `"8"`을 MySQL에서 재현해 로그인·갱신,
  현재 학적 commit, 과거 데이터 보존, 과거 교환학생 프로필 발급을 확인한다.
- 학부·대학원 교환학생 각각의 재학·휴학에 대해 로그인·갱신 및 회원신청 학적 검사를 확인한다.
- 학위 정보가 없는 교환학생의 재학·휴학 로그인·갱신과 학생 API 접근, 학부 전용 API 차단, 준회원 분류를 확인한다.
- 대표자 후보·변경, 등록 통계, 총람의 정회원 수가 같은 기준을 따르는지 확인한다.
- 테스트는 가상 사용자·학번과 별도 MySQL 테스트 DB를 사용한다.

실행 명령:

```sh
pnpm --filter api test:integration --runInBand --testTimeout=30000 sso-login-failure.spec.ts
pnpm build:api
pnpm pre-push:parallel
```

`pre-push:parallel`은 단위 테스트를 통한 MC/DC 및 형식·린트·아키텍처 가드를 확인한다.
통합 테스트에는 이름에 `test`가 포함된 격리된 DB의 `TEST_DATABASE_URL`이 필요하다.
