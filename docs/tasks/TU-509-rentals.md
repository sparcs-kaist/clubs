# 물품 대여와 상근일 관리

[Notion Task TU-509](https://app.notion.com/p/416c25603b0b81beb637dcceee5f6a33)

## 데이터

- `office_hour`는 시간, 휴무 여부, 공개 안내와 내부 메모의 변경을 별도 행으로 기록한다. 캘린더는 날짜별 변경 시각이 가장 최근인 행을 조회하며, 시각이 같으면 ID가 큰 행을 사용한다.
- `rental_item`은 품목명, 총수량, 신청 가능 여부와 대여 기한의 종류(`durationType`)·숫자(`durationValue`)를 저장한다.
- `rental_reservation`은 품목·동아리·신청자 ID와 예약할 때 선택한 수령·반납 상근 행의 ID를 참조한다. 처리 수량, 신청 당시 사용자 정보에서 가져온 연락처와 사용 목적, 확정된 기간 정책과 기본 기한, 상태 및 승인·인도·반납 확인을 저장한다. 승인 시각(`approvedAt`)과 처리 집행부원 ID(`approvedByExecutiveId`)는 상태와 별개로 기록한다.
- `rental_extension`은 변경 전후 반납 상근 행의 ID, 사유, 집행부 처리자와 시각을 저장한다. 연장을 조회할 때 서비스에서 해당 예약의 연장 기록인지 확인한다.

연관 데이터는 ID로 조회하며, 이 기능의 테이블에는 외래 키 제약을 생성하지 않는다.

## API

공유 Zod 계약은 `@clubs/interface/api/office-hours`와 `@clubs/interface/api/rental/v2`에 있다. 날짜는 KST `YYYY-MM-DD`, 시각은 UTC ISO 8601을 사용한다.

신청·일정 조정·연장에는 화면에서 선택한 상근일의 `date`, `opensAt`, `closesAt`을 보낸다. 그 사이 상근 시간이 바뀌거나 휴무가 되면 서버가 요청을 거절한다.

공개 안내(`publicMemo`)는 학생용 캘린더에 표시되며 휴무 사유 등을 적는 데 사용할 수 있다. 내부 메모(`internalMemo`)는 집행부만 읽을 수 있다. 둘 다 최대 500자다. 수정 요청에서 각 필드를 생략하면 기존 값이 유지되고, `null`이나 빈 문자열을 보내면 해당 메모가 삭제된다.

공개 캘린더는 한국 시간 기준 오늘을 선택한 상태로 열린다. 날짜를 선택하면 그 날짜의 상근 시간(`HH:MM~HH:MM`), 휴무 또는 상근일이 아닌 상태를 표시하고, 공개 메모가 있을 때만 안내를 덧붙인다.

대여 기한은 `DAYS`와 `OFFICE_HOURS` 중 하나와 양의 정수로 지정한다. `DAYS/7`은 수령일에서 7일 뒤까지 열리는 상근일 중 가장 늦은 날, `OFFICE_HOURS/3`은 수령일 다음 세 번째 상근일까지다. 휴무는 계산에서 제외한다. N번째 상근일까지 등록되지 않았어도 이미 등록된 반납 후보는 선택할 수 있다. 예약에는 신청 당시 기한 설정과 등록된 상근일로 계산한 기본 반납 한도를 저장한다.

신청 화면은 대표 동아리를 자동으로 채우며 연락처를 입력받지 않는다. 서버가 저장된 사용자 연락처를 신청 내역에 기록하고, 연락처가 없어도 신청할 수 있다. 대표자·대의원 동아리가 없으면 안내 모달을 확인한 뒤 이전 화면으로 돌아간다. 해당 동아리의 신청 목록은 대여 폼 아래와 대표 동아리 관리의 회원 명단 아래 접이식 “대여 신청” 섹션에서 조회한다.

상근일 GET 조회에서 `to`를 생략하면 `from` 이후 게시된 일정을 조회한다. 종료일을 지정한 조회와 기본 일정 생성은 최대 366일 범위를 사용한다.

| 권한 | API | 동작 |
| --- | --- | --- |
| 공개 | `GET /office-hours?from&to` | 운영 시간, 휴무, 공개 안내를 포함한 상근일 목록 |
| 공개 | `GET /rentals/items` | 신청 가능한 품목 목록 |
| 공개 | `GET /rentals/items/:id/return-options?pickupDate=…` | 수령 회차, 반납 후보별 승인·반출분을 뺀 가용 수량, 같은 기간의 승인 대기 신청 수량(`requestedQuantity`), 당일 반납 전 가용 수량 |
| 학생 | `GET /student/rentals/eligible-clubs` | 현재 대표자·대의원으로 신청할 수 있는 동아리 |
| 학생 | `POST /student/rentals` | 동아리, 품목·수량, 수령·반납 일시, 목적, 요청 UUID로 승인 대기 신청. 연락처는 서버가 사용자 정보에서 조회 |
| 학생 | `GET /student/rentals?clubId=…` | 해당 동아리의 현재 대표자·대의원만 동아리 전체 예약 조회. `clubId`를 생략하면 본인 목록 |
| 학생 | `GET /student/rentals/:id` | 신청자 또는 해당 동아리의 현재 대표자·대의원만 상세 조회 |
| 학생 | `POST /student/rentals/:id/cancel` | 본인 예약을 인도 전에 취소 |
| 집행부 | `GET /executive/office-hours?from&to` | 상근일 관리 목록과 날짜별 공개 안내·내부 메모 |
| 집행부 | `POST /executive/office-hours/generate` | 범위 내 미등록 월~목에 21:00–22:00 일정 생성 |
| 집행부 | `PUT /executive/office-hours/:date` | 해당 날짜의 시간, 휴무 상태, 공개 안내·내부 메모 등록·수정 |
| 집행부 | `GET /executive/rental-items`, `POST /executive/rental-items`, `PATCH /executive/rental-items/:id` | 품목 관리 |
| 집행부 | `GET /executive/rentals`, `GET /executive/rentals/:id` | 상태·연체·상근일 조건으로 목록 조회, 인계 메모와 연장 이력 조회 |
| 집행부 | `POST /executive/rentals/:id/approve` | 선택 입력인 `quantity`로 신청 수량 이내의 실제 승인 수량을 지정하고 재고·선행 신청 확인 후 처리자·시각 기록. 생략 시 신청 수량 사용 |
| 집행부 | `POST /executive/rentals/:id/checkout`, `POST /executive/rentals/:id/return` | 실제 인도·반납 확인. 수령 확인의 `quantity`는 승인 수량 이내로 지정하며 생략 시 승인 수량 사용. 상근 시각과 무관하게 가능하며 인도 메모는 선택 입력 |
| 집행부 | `POST /executive/rentals/:id/cancel`, `POST /executive/rentals/:id/reject` | 인도 전 사유를 기록하고 예약 해제 |
| 집행부 | `PATCH /executive/rentals/:id/schedule` | 수령 전 수령일, 진행 중인 예약의 반납일 조정 |
| 집행부 | `POST /executive/rentals/:id/extend` | 기본 기한을 넘는 연장과 처리자 기록 |

학생 예약 응답의 `canCancel`은 신청자 본인의 수령 전 예약일 때만 참이다. 같은 동아리의 다른 대표자·대의원에게는 조회만 허용하며, 취소 API도 신청자 여부를 별도로 검사한다.

## 규칙

- 상태는 `REQUESTED`(신청 대기) → `RESERVED`(집행부 승인·예약 확정) → `CHECKED_OUT`(실제 수령) → `RETURNED`(반납 완료) 순서다. 수령 전에는 신청자 취소 또는 집행부 취소·반려가 가능하다. 새 승인 절차 도입 시 기존 미수령 `RESERVED` 내역은 한 번의 데이터 전환으로 `REQUESTED`로 바꾸고 집행부가 다시 승인한다. 런타임에서는 승인 메타데이터의 유무로 상태를 판단하지 않는다.
- 승인 대기 신청은 확정 재고를 점유하지 않는다. 반납 선택지는 승인·반출된 예약을 뺀 최대 수량과, 해당 대여 기간에 겹치는 승인 대기 신청의 수량 합계를 따로 표시한다. 승인할 때 품목 잠금 아래에서 재고를 다시 검사하며, 충돌하는 선행 신청이 있으면 먼저 처리하도록 안내한다.
- 신청 수량이 최대 가용 수량에서 승인 대기 수량을 뺀 값을 넘으면 승인 수량이 줄어들 수 있음을 안내한다. 최대 가용 수량 자체를 넘으면 최대 수량을 표시하고 신청을 막는다. 당일 반납 안내는 최대 가용 수량 이내에서 당일 반납 전 가용 수량을 넘는 유효한 신청에만 표시한다.
- 승인과 수령 확인은 각각 신청 수량과 승인 수량을 기본값으로 제공하며, 1개 이상 그 이하로 조정할 수 있다. 재고 검사는 실제 처리 수량으로 수행하고 해당 수량을 저장한다. 처리 후 같은 수량의 재시도는 중복 반영하지 않으며 다른 수량으로 재시도하면 거절한다.
- 품목별로 지정한 일수 또는 수령 다음 N번째 상근일을 기본 반납 한도로 사용한다. 연장은 기본 한도에서 일수 기준 14일, 상근 횟수 기준 7일을 더한 범위에서 가능하다.
- 승인된 예약은 수령 상근 시작부터 반납 상근 시작 직전까지 재고를 점유한다. 수령 확인에는 상근 시작·종료 시각이나 휴무 제한을 두지 않으며, 실제 잔여 수량과 먼저 승인된 예약의 재고를 보호한다. 예정일보다 일찍 수령한 물품은 실제 수령일부터 재고를 점유한다. 연체는 반납 상근 종료 시각부터 표시한다.
- 당일 반납 전 가용 수량을 초과하는 예약이 있으면 해당 수령자와 반납자에게 예약 화면에서 안내한다.
- 휴무나 시간 변경의 영향을 받는 예약은 기존 시간을 표시하고 일정 조정이 필요함을 안내한다.
- 같은 품목에 대한 신청·승인, 재고 수정과 인도·반납은 품목 행을 기준으로 직렬화한다. 동일 요청 UUID의 재시도는 같은 예약을 반환한다.

## 운영 시작

스키마 반영 후 집행부가 실물 수량을 확인해 품목을 등록하고, 공개할 기간의 상근일을 생성한다. 등록된 품목과 상근일을 기준으로 새 신청을 받는다.

이미 테이블을 만든 환경에는 배포 전에 nullable 승인 시각·처리자 컬럼을 추가한다. 새 API 배포 후에는 기존 `RESERVED` 중 `approved_at`이 비어 있는 내역만 `REQUESTED`로 전환한다. 이는 이전 구현에서 자동 확정된 내역을 식별하는 일회성 데이터 전환이며, 새 승인 이력이 있거나 실제 반출된 내역은 보존한다.
